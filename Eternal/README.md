# Xuse/Eternal resource archive 脚本提取与回封

外部工具显示的资源体系标签为 `Xuse/Eternal resource archive`。本工具只处理该体系中已解出的脚本数据：当前支持带同名 `.debug` 文件的 `NORI` v65536 `.bin` 脚本容器，不负责外层资源归档的解包或重建。工具解析容器块、脚本参数、字符串对象和引用站点，提供文本及有限 ASM 编辑面，并在重建时校验源绑定、校验和、引用和未编辑数据。

当前证据来自两组独立样本：

| 样本组 | 文件 | 脚本 | 总字节数 | 参数形态 | 对话条目 |
|---|---:|---:|---:|---:|---:|
| A | 621 | 310 | 11,036,347 | 196 | 29,829 |
| B | 947 | 473 | 16,143,734 | 243 | 42,523 |

两组合计覆盖 245 种已登记参数形态。计数用于描述当前样本，不代表任意 `NORI` 容器或其他 VM 方言都受支持。完整布局和证据边界见 [vm_analysis.md](vm_analysis.md)。

## 环境

- Python 3.11 或更新版本。
- 核心解析、导出和回封仅使用 Python 标准库；界面使用 Tkinter。
- Windows 文件拖放可选用 `windnd`；未安装时可通过浏览按钮选择路径。

## 图形界面

在工具目录运行 `启动界面.pyw`，或使用：

```powershell
python run_gui.py
```

1. 选择包含 `.bin` 和同名 `.debug` 的目录，或选择单个 `.bin`。
2. 选择源编码和目标编码。当前样本源文本为 CP932。
3. 选择文本、ASM 或两种输出，点击“输出文本”。
4. 在项目目录的 `texts/` 中只改 `●` 行；原文 `○`、条目编号和定位注释是校验锚。
5. 选择项目目录作为回封输入，为回封结果指定新的输出目录。
6. 先预览变更与策略，再执行。回封输出不会覆盖已有目录。

## 命令行

从工具目录运行；路径请替换为本地的源目录和输出目录：

```powershell
python disassembler.py "<source-folder>" -o "<project-folder>"
python assembler.py "<project-folder>" -o "<rebuilt-folder>" --preview
python assembler.py "<project-folder>" -o "<rebuilt-folder>"
```

目录输入默认在源目录旁创建 `<source-name>_text`；单文件输入以文件名主体为前缀。旧协议分别使用 `_text_v1` 或 `_text_segments`，仅导出结构清单使用 `_disasm`。从项目回封时默认创建 `<source-name>_rebuilt`，旧协议使用对应的 `_rebuilt_v1` 或 `_rebuilt_segments`。指定 `-o` 可选择其他新目录，工具拒绝覆盖现有输出，也拒绝把输出放进受保护的源或项目目录。

常用选项：

- 导出同时生成文本与结构清单：`--mode both`。
- 只生成结构清单：`--mode disasm`。
- 输出 IR 研究快照：`--with-ir`。
- 显式选择投影协议：`--text-projection message-v2`、`message-v1` 或 `segments-v1`。
- 项目移至其他位置后指定原始来源：回封时使用 `-s "<source-folder>"`。
- 限制修改策略：回封时使用 `--strategy auto|identity|in_place|pointer-rewrite`。

`message-v2` 是当前默认协议。`message-v1` 和 `segments-v1` 用于导入已有项目；工具按项目清单中的版本和源哈希检查兼容，不会静默忽略差异。

## 项目文件

| 路径 | 内容 |
|---|---|
| `*_text/texts/*.bin.txt` | UTF-8 文本编辑面，保留原文行和译文行 |
| `*_text/asm/*.asm.txt` | 可选有限结构编辑面，只允许修改已有 `.string` 值 |
| `*_text/project.json` | 工具版本、源清单、哈希、编码和投影协议；不要手工编辑 |
| `*_text/_work/reports/` | 提取统计、形态、引用和往返报告 |
| `*_rebuilt/` | 重建的 `.bin` 及原样保留的 `.debug`、`.var` |
| `*_rebuilt/_work/` | 重定位计划、差异归因与审计结果 |
文件名中的 `_text`、`_rebuilt` 说明数据用途；协议版本保存在 `project.json` 和文本头部。

## 文本协议

每个条目由只读原文行 `○` 和可编辑译文行 `●` 组成。保留文件头、索引、标签、策略和对象编号，只改译文内容。锁定标签不能编辑；`misc` 条目须先在对应注释中写入 `reviewed=true`。

同一 `text` / `speak` 命令中的多个正文槽在 `message-v2` 中映射为一个逻辑条目。槽内原始内容、成员对象和行首缩进记录在项目报告中；不同命令不会合并。示例使用虚构文本：

```text
# idx=00000010 off=0x00000120 tag=msg object_id=M00000120 policy=translatable
○00000010○msg○第一段\n第二段
●00000010●msg●第一段\n第二段
```

译文中的字面 `\n` 表示显示行边界；不要用真实换行拆开条目。原始文本中的反斜杠控制码会转义显示，编辑时保留其值和顺序。不要新增、删除、复制或重排条目。

当前文本策略限制为每行 25 个字符、最多 3 行；这是本适配配置的显示约束，不是 NORI 容器格式的通用定律。工具不会把超长行自动切开。行数可以不同于源槽数：短行按序写入现有槽，多余的显示行可写入最后一个槽的 LF 字节 `0x0A`，未用尾槽清空。每个物理字符串仍受 u16 字节长度上限约束。未编辑条目保留原始字节。

ASM 面显示物理字符串对象。若文本面与 ASM 面同时编辑同一消息，只有逻辑内容一致时才能合并；内容不同会报冲突。

## 编码与边界

源编码按样本清单严格校验；当前两组文本均为 CP932。目标编码只控制新写入文本的字节编码，不会改变目标程序的编码能力。无法编码的字符会拒绝回写，未编辑字节不转码。

回封支持既有字符串对象的等长或变长更新，不支持插删指令、改控制流、增加引用对象或重排脚本。`.debug` 必须与 `.bin` 同名且来自同一版本；`.var` 仅作为不透明数据保留。新的 NORI 版本或未知参数形态会停止处理，需先补充格式证据。

## 验证范围

支持范围依据两组独立样本的静态结构分析建立。容器重解析和回封自检不能证明目标程序运行时加载成功。

- 支持范围限于已声明的 Xuse/Eternal 资源体系中已解出的 NORI v65536 容器和已登记参数形态。
- 指令数据可定位，但未声称完整恢复 VM 控制流语义。
- 未验证外层归档重建、宿主运行时行为、混合编码显示或超过 2 GB 的资源。
- 新结构出现时先保存原始样本、哈希和解析报告，再扩充适配器；不要放宽校验来跳过未知字段。

开发与格式证据见 [vm_analysis.md](vm_analysis.md)。
