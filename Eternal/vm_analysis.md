# Xuse/Eternal resource archive 已解出脚本中的 NORI v65536 容器分析

外部工具显示的资源体系标签为 `Xuse/Eternal resource archive`。本文记录该体系中已解出脚本数据的容器结构、参数边界、文本引用关系和当前适配能力；当前解析器识别的具体容器签名为 `NORI`，版本为 `65536`。证据来自两组独立样本；样本标签 A/B 只用于区分数据集。工具能无损解析和重建已登记结构，不据此宣称恢复了完整 VM 执行语义，也不处理外层资源归档。

## 样本基线

| 样本 | 文件 | `.bin` 脚本 | 字节数 | 参数形态 | 文本对象 | 名称绑定 |
|---|---:|---:|---:|---:|---:|---:|
| A | 621 | 310 | 11,036,347 | 196 | 81,653 | 30,433 |
| B | 947 | 473 | 16,143,734 | 243 | 123,233 | 46,361 |

每组有一个 `.var`，其余为同名 `.bin/.debug` 文件对。两组联合出现 245 种参数形态、187 个 opcode 编号。B 组比 A 组多 49 种形态和 26 个 opcode 编号。两组共 1,568 个文件均有基线路径、长度和 SHA-256 清单。

证据词汇：`observed` 表示直接读取的字节或调试源码；`derived` 表示由明确规则可重复计算；`inferred` 表示仍缺独立确认；`unresolved` 表示当前用途未知。计数和能力只描述这两组数据。

## 解析范围

容器解析基于文件数据与配对 `.debug` 的结构对照。工具未反编译宿主程序、未恢复完整 CFG，也未启动目标程序。

能力分级采用结构证据：T0 保留区间及原始字节；T1 证明单元边界和字节序；T2 证明数据字段、文本对象和引用站点；T3 证明完整指令边界；T4 证明控制流和必要执行语义。本适配器对容器和已知数据字段达到 T2；opcode 参数形态登记不等于 T3/T4。

磁盘布局为：NORI 容器 → 六个顺序数据块 → 表记录、code 参数单元和 pool 对象。未观察到该批容器再包一层压缩。`.var` 未解析，仅按不透明数据保留。

## EV_CONTAINER：容器布局

文件以 ASCII `NORI` 开始，版本字段为 65536。40 字节头按小端 `<10I` 解释：

| 字段索引 | 含义 |
|---|---|
| 0 / 1 | 签名值 / 版本 |
| 2 / 3 | labels 表条数 / 存储长度 |
| 4 / 5 | table1 表条数 / 存储长度 |
| 6 / 7 | table2 表条数 / 存储长度 |
| 8 / 9 | code 长度 / pool 长度 |

块顺序为 `header, labels, table1, table2, code, pool`。每块后有 2 字节校验值。文件长度必须等于 40 字节头、各块声明长度和六个校验字段长度之和；解析器拒绝多余尾部和不匹配边界。

表项由未变换的 `u32 identity`、XOR 变换后的 `u32 length` 和变换后的字符串字节组成；XOR key 为 `0x53`。表项必须恰好结束于表块边界。表项按结构字段处理，不因内容可读而自动认定为显示文本。

pool 字符串字节逐字节 XOR `0x53`。显式长度决定读取范围，没有 NUL 终止符。pool 同时包含未变换的消息元数据；不能把整个 pool 一律 XOR。无法解释的字段、非文本 code 单元和旧文本尾部均保留原字节。

## EV_CHECKSUM：分块校验

校验算法为 `binascii.crc_hqx(data, 0)`，即初值为零的 CRC-16/CCITT，结果以大端 2 字节保存。header、code、pool 对磁盘逻辑字节计算；三张表先还原 XOR，再对逻辑记录序列计算。

全部 `.bin/.debug` 样本的零编辑解析与重序列化均重算六个校验值并与输入逐字节比较。独立检查器重新计算块边界、表记录、XOR 和 CRC；编辑样本也经过该检查。

## EV_DEBUG：指令与参数边界

同名 `.debug` 与 `.bin` 的表及 code 区长度一致。debug code 按 8 字节单元排列：命令头是 `<u16 opcode, 0xFFFF, u32 source_record_offset>`，参数单元填充为 `0xFF`。每个命令头引用一个唯一源码记录；除路径记录外，全部源码记录都被使用。

debug pool 是连续的 `<u32 source_line, u32 byte_length>` 与 CP932 源码文本记录。命令头的源码偏移、opcode 和源码命令名逐项交叉核对。偏移所指向的路径仅作为证据字符串，不访问该路径。

竞争假设：命令头中的 count 不总等于实际参数单元数。opcode 14 等形态提供反例，B 组还包含更多例外。因此参数边界取自 `.debug` 的命令头集合，而不是统一 count 步进。头中 count 原值保留；两组样本共同穷举出 245 种 `(stored_count, actual_argument_kinds)` 组合。

早期研究中的 `errors` 字段包含该 count 假设的反例和当时尚未登记的形态，不能作为当前适配失败清单。当前已登记参数形态以解析器中的声明表为准；未知形态会停止处理，不按统一 count 假设继续读取。

## EV_REFERENCES：字符串对象与引用

参数单元格式为 `<u16 kind, u16 length, u32 value>`。kind 5 的 length 是字符串字节长度、value 是 pool 相对偏移；kind 3 的 value 指向 pool 中 8 字节消息元数据。元数据用途未完全恢复，只检查范围并原样保留。

每个文本对象由 `(pool_offset, raw_length)`、原始字节和全部引用站点标识。对象身份与存储偏移分开；站点按对象 ID 联接，不做数值全局替换。脚本相对身份与源 SHA-256 一起生成，避免同名文件跨来源误合并。

独立检查器从 debug 的 `0xFF` 参数单元重新发现所有 kind-5 字段。原始和重建后的站点集合相同。两组 pool 均由已证明的字符串对象与元数据范围完整分区，没有间隙或重叠。没有使用可打印字符扫描来推断对象边界；未观察到无引用字符串。零长度索引单独验证。

两组原始字符串均可用 CP932 严格解码。未来遇到不可解码文本时必须保留完整原字节并冻结，不允许用替换字符或忽略错误后回封。

## EV_TEXT_ROLES：文本角色和名称绑定

opcode 1 `text` 与 opcode 60 `speak` 的调试源码形态用于确定正文与名称参数。可观测到的角色如下：

| 标签 | 结构来源 | 当前权限 |
|---|---|---|
| `msg` | `text` / `speak` 消息正文 | 可编辑，需保留 anchor |
| `name` | 源码角色标记对应的字符串参数 | 可编辑，需保留 binding |
| `choice` | opcode 102 `dest`、103 `destex` 的字符串参数 | 可编辑，条件参数保留 |
| `ui` | opcode 54 `SaveTitle` 字符串参数 | 可编辑 |
| `system` | opcode 209、211、212 的对话框参数 | 可编辑 |
| `label` | 表项及已登记资源、脚本、分支引用 | 冻结 |
| `misc` | 部分 `callr` 动态参数及用途未证明的字符串 | 需人工复核 |

绑定根据同一命令的显式名称参数生成，不从邻近消息推测人名。A 组有 30,433 条名称绑定，B 组有 46,361 条；当前样本没有多名称歧义。遇到同一正文对象绑定到不一致名称时，工具拒绝任选一个。

所有字段均保留原字节、定位和站点证据。当前样本没有靠文本外观推断角色的 heuristic 项。A 组有 378 个用途未定条目，B 组有 654 个；这些条目保持 `misc` 并要求明确复核。

## EV_MESSAGE_PROJECTION：逻辑消息与物理文本槽

同一 `text` / `speak` 命令中有序的正文参数属于一个消息 anchor；不同命令保持独立。`message-v2` 将该 anchor 投影为一个逻辑编辑条目，并用字面 `\n` 表示显示行边界。人名和其他角色仍为独立条目。映射依赖命令边界，不按句号或相邻字符串猜测。

| 指标 | A | B |
|---|---:|---:|
| 单槽消息 | 14,080 | 19,846 |
| 双槽消息 | 12,655 | 17,336 |
| 三槽消息 | 3,094 | 5,341 |
| 逻辑消息条目 | 29,829 | 42,523 |
| 全部逻辑投影条目 | 62,810 | 95,215 |
| 物理正文对象 | 48,672 | 70,541 |
| 全部物理文本对象 | 81,653 | 123,233 |

`message-v2` 文本头和项目清单记录协议版本。原始字面反斜杠控制码在投影中转义，避免与分行标记混淆；导入时先还原控制码，再解析显示行。旧 `message-v1` 和无投影标记的 `segments-v1` 项目仍可按其原协议读取，源清单哈希仍严格校验。

未编辑消息不会重新分配物理槽，因此原始槽逐字节保留。编辑时每行最多 25 个字符、每条消息最多 3 行；这是当前配置的显示策略，不是容器级限制。译文按序装入已有物理槽，多出的显示行可在最后一个槽中编码为 LF (`0x0A`)；未使用尾槽清空，脚本参数数量不变。保留原有行首全角缩进，但不将其计入译文字符数。控制码保持原值和顺序。每槽还有独立的 u16 字节长度上限 `65,535`。

这些行宽值来自本次适配的外部显示约束。静态回封只能证明行标记和脚本引用关系，不能证明某宿主的字体度量或窗口实际呈现。

## 方言注册和项目兼容

`opcodelist.py` 是 opcode 编号与参数 kind 形态的声明式注册表。245 种形态均在联合样本中命中。单个来源未覆盖的形态会记录为 inherited，并保留另一来源证据；不能通过删除未命中声明来伪造覆盖率。

本适配器保留了早期 profile 哈希 `6569ffe314502eff3fc6bc0dbdc3804fa56fa94c6aed8309e15ca3f690197ae8` 的显式兼容入口。允许旧项目导入前，先比对其文本投影、角色、权限、名称绑定和引用站点回归；兼容规则不跳过哈希检查。

未知 opcode 或参数形态会报 `UNKNOWN_SHAPE` 并停止。当前能力不包括任意 NORI 字节流的自动降级浏览、指令语义修改或控制流编辑。

## 重建与验证闭包

变更前只读解析源、项目清单和编辑面。无变更使用 identity；新串不长于旧串时可原位更新；增长文本追加到 pool 末尾并更新该对象的长度和偏移引用。禁止 full-layout 重排或指令插删。

变长重建需更新 pool 长度、受影响引用和相应 CRC。回封后以原 `.debug` 重解析每个输出，验证目标字节、人名绑定、未编辑对象、元数据和站点集合。完整差异归因分别记录保留区间与变化区间；即使某个非引用常量的数值恰好等于文本偏移，也不将它当作引用更新。

基础格式上限为单字符串 u16 长度 `65,535` 字节，pool 长度为 u32。格式不提供 NUL 终止容量推断或未证实的 padding 扩容。每次编码都按目标编码的实际字节数检查。

预览后再次校验源清单和编辑文件哈希。输出先写入同卷 staging，读盘验证通过后原子提交到新目录；取消或异常时不把未完成目录报告为成功。未编辑 `.debug` 通过 parse→serialize，`.var` 明确作为 opaque copy。

## 静态验证结果

静态分析基于两组独立样本，共 1,568 个文件、245 种联合参数形态。静态结构检查与回封自检不能证明执行语义等价或目标程序运行时加载成功；运行时状态为未验证。

此前验证覆盖如下范围：

| 项目 | 证据边界 |
|---|---|
| 源基线 | 文件集合、大小和 SHA-256 与清单一致 |
| 零编辑 | 两来源输出重建后逐字节相等 |
| 结构覆盖 | 所有已登记参数形态均有观测来源或 inherited 来源 |
| 引用完整性 | kind-5 字段、对象集合、pool 分区及站点数独立核对 |
| 文本编辑 | 两来源均包含长、短、等长文本、人名、选项及显式行标记更新 |
| 差异审计 | 未编辑文件和非站点字节保持，变化区间可追溯到对象、引用或 CRC 字段 |
| 负例 | 篡改 anchor、标签、控制码、项目集合、编码、CRC、源哈希、路径和未知形态时拒绝 |

以上范围只描述这两组样本，不代表其他容器版本或资源体系。完整计数不能替代对新样本的结构分析。

## 未覆盖范围

- 未反编译宿主执行循环，未重建完整 CFG；不支持任意控制流修改。
- 未验证外层归档索引、压缩格式和归档写回。
- 未验证目标程序加载、存档读写、字体度量或实际显示效果。
- 未证明宿主接受除原始 CP932 外的编码；静态 GBK/UTF-8 编码测试不代表运行时支持。
- 未测试超过 2 GB 资源的峰值内存或吞吐量。
- 不支持删除全部引用后的孤立字符串编辑，也不猜测未解析 `.var` 的语义。

出现新容器版本或参数形态时，应保存输入哈希、最小结构反例和失败报告；补充证据前保持原字节，不要放宽解析门槛。
