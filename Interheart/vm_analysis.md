# 格式与验证说明

本文供维护者核对当前适配器。结构规则来自解析器及其输入校验；
实际文件数量、哈希、覆盖率和回封结果以每次作业的报告为准。
这不是跨作品、跨版本的通用格式证明。

## 格式边界

当前实现读取同级的归档和解包目录，并处理其中的源文本文件、
指针索引文件、文本池文件与 `.spt` 文件。这些文件名和字段由适配器
声明，不是任意文件的识别规则。

| 层 | 已处理范围 | 未处理范围 |
|---|---|---|
| FPK | 带加密索引的固定宽度记录、ZLC2 数据块 | 其他索引或压缩变体 |
| SPT | 定长记录边界和已确认的文本引用字段 | 非文本指令语义和控制流 |
| 指针索引/文本池 | ID、文本偏移、长度及 UTF-8 文本记录 | 未验证的其他编码、记录结构 |
| 源文本 | 与文本 ID 对应的行及说话人前缀 | 其余行的完整语义 |

归档索引每条 36 字节，其中名称字段占 24 字节；未知字段按原字节保留。
未改的数据块重放原字节，修改块重新编码。重新编码的压缩字节不要求与原文件相同，
但必须能重读并得到预期内容。

## 解析与引用

- SPT 头部为小端记录数，后续每条 32 字节、八个小端有符号整数。
  文件长度和记录数必须相符。只能据此确认记录边界，不能据此解释所有指令。
- 已确认的文本记录由声明的 opcode 和 kind 定位。记录中的文本 ID、
  源行范围及源行内的文本锚须一致。
- 指针索引由签名、记录数和连续的 `<III>`（ID、偏移、长度）组成。
  文本池每条按索引指定的字节范围严格解码；记录必须无重叠、无缺口。
- 文本记录按声明的分隔规则分为说话人和正文。存在说话人时，还需与源行前缀对应；
  人名可作为独立 `name` 编辑对象，正文为 `msg` 或 `choice`。
- 回封按 ID 改写 PTR 的偏移和长度，并核对 SPT 引用与源行锚。
  不通过扫描旧偏移的数值来猜引用。源行数和非目标资源保持不变。

已确认的文本及其引用仅申报 T2。其余 SPT 定长记录为 T1；
源文本的未解析区域只申报原字节保留。没有证据支持完整指令级 T3/T4。

## 证据

| 证据 ID | 等级 | 核对方式与范围 |
|---|---|---|
| `EV_SPT_32` | 直接观察 | 记录数与文件长度吻合；只证明边界。 |
| `EV_PTR_TXD` | 直接观察 | PTR 的 ID、偏移和长度连续且覆盖 TXD；逐条严格解码。 |
| `EV_TEXT_JOIN` | 结构推导 | SPT 文本 ID、源行锚、索引 ID 和文本池正文逐项交叉核对。 |
| `EV_NAME` | 结构推导 | 文本池说话人字段与源行前缀一致；不靠相邻条目猜人名。 |
| `EV_CHOICE` | 结构推导 | 选择区块锚及其计数只用于已确认的文本 ID。 |
| `EV_FPK_GARBRO` | 实现对照 | 归档索引规则对照 GARbro `ArcFPK.cs`；每项边界需在本次输入中复核。 |
| `EV_ZLC2_GARBRO` | 实现对照 | 数据块的解码规则对照 GARbro 的 ZLC2 读取逻辑；重建后逐项回读。 |

证据 ID 与字段定义见 `opcodelist.py`；解析和回封实现分别见
`extract_text.py`、`disassembler.py`、`assembler.py` 与 `fpk_repack.py`。
实际检查结果见导出目录的 `_work/reports/` 和回封目录的 `report.json`。

## 验证与未决

- 零编辑：源归档、索引及文本记录逐字节往返。若不一致则停止回封。
- 有编辑：重读输出，逐 ID 核对新值、说话人、引用和源行位置；
  未编辑对象及归档条目不得无故改变。
- 字节覆盖与文本发现是两件事。报告中即使 `byte_coverage=1.0`，
  也不能推断未知指令已被理解或其他布局的文本已找全。
- 未验证：目标程序的实际载入与显示、跨作品/版本兼容性、
  其他 FPK 变体、非 UTF-8 文本池，以及指令或控制流编辑。

新增格式或来源时，先建立新的结构证据和正反例，
再开放相应的提取与回封能力；不能只修改标识或跳过校验。
