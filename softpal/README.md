# SoftPal 文本工具

用于提取、编辑和回封 `SCRIPT.SRC` 与 `TEXT.DAT`，支持明文和加密资源。
当前适配已经核对的 Sv20 脚本格式；其他脚本版本需要先验证指令和调用参数。

## 使用

运行 `softpal_tool_gui.py`，选择项目并确认原始脚本、文本和独立输出目录。

1. 点击“反汇编 + 分析”。
2. 点击“导出译文”，或按场景导出。
3. 编辑 `translate_dump.txt`：`○` 行保留原文，只修改 `●` 行的文字，编号和标签保持一致。
4. 点击“导入并回封”，选择需要的明文或加密输出模式。
5. 使用同一轮生成的 `SCRIPT.SRC` 和 `TEXT.DAT` 一起替换资源。

更新人名／正文判定后，旧反汇编数据需要重新生成；已有译文先保留备份。
回封引用修复可读取已有 dump，按对应原始资源重新核对引用。
脚本地址和锚点编号只用于显示定位参考，不限制回封范围。

如果输入曾把“人名＋对白”的连续显示列表粘贴到原 DAT 记录中，工具会检测人名槽与正文槽
同时出现完整对白的矛盾。存在与资源目录同名的原始 PAC 时，会核对脚本版本、全部引用身份
和完整文本列表，只有能唯一还原时才生成 `source_recovered` 恢复副本并保留可确认的改文。
原始输入不被覆盖，后续回封使用恢复副本；缺少原包、漏行或有无法确认的编辑时停止并说明原因。
原包在其他位置时，CLI 的 `dump` 可通过 `--reference-pac` 指定。

CLI 的完整参数可通过以下命令查看：

```powershell
python -X utf8 -B -m softpal_roundtrip --help
```

## 已修复的问题

- 人名和正文标签反转：已知消息调用按参数槽位区分标志、正文、人名和行号；短独白不会因长度或括号被当成人名。
- 变长回封后选项丢失首字：按调用参数、变量来源和格式化文本参数识别引用，更新整份脚本中的全部相关位置。坐标、行号和函数编号等数值保持原值。
- 扩展消息调用导致分析中断：补充 `0x20012`、`0x20013` 的四参数布局和 `0x20014` 的三参数布局，避免把恰好等于文本地址的数值误认成人名；回封同时识别这些消息及 `0xA0015` 章节标题的引用。
- 分场景译文混入资源模板和日志：导出依据已识别的文本类别及消息配对，保留场景边界、正文、人名、选项和可见展示文字，略过内部条目。正常英文和带格式占位符的可见文字保留。
- 连续显示文本误填 DAT 后，人名、正文和场景编号错位：从同版本原包验证并恢复独立记录，重新定位脚本引用；无法验证时拒绝继续导出错误标签。
- 后续场景被并入同一个文件：新反汇编数据从已确认的场景调用参数取得边界，保留连续边界、无对白短场景和不含数字的场景名称。边界标为 `scenario`，旧边界标签仍可校验导入。
- 无法解码的字节导致提取中断：JSON 通过标准 Unicode 转义保留原字节，双行文本使用明确的字节转义，UTF-8 和 UTF-16 导出均可重新导入回封；场景文件名和错误摘要也能正常生成。

完整 `translate_dump.txt` 仍保留全部 DAT 条目，并显示各自的原始分类。分场景导入时未导出的
内部条目保持原值。旧版场景整理生成的标签可自动兼容，编号和第一行原文仍须通过校验；
无需手工修改旧译文中的这些标签。
重新导出会保留 dump 中已有的译文，原文对照行继续使用当前源的原文。

存在无法解码的字节或实际换行时，译文文件头会带 `# SOFTPAL_TEXT_ESCAPE_V1`。
此时 `\xNN` 表示保留的原字节，`\\` 表示字面反斜线，`\n`、`\r`、`\t` 分别表示换行、回车和制表符。
保留版本标记，只改译文行；需要保留原字节时不要改相应的 `\xNN`。
没有此标记的旧文件继续按原规则读取，反斜线保持字面含义。已有乱码按源值保留，不自动猜测或替换字符。

输出前会核对源哈希，重新解析所有文本和引用，检查脚本差异范围并验证加密往返。
校验失败时停止写入，普通文件替换异常会恢复此前输出。

## 日志

界面显示中文摘要，包括导入条数、译文改动数、引用更新数、略过的内部条目数和输出模式，保留最近 500 行。
错误日志保留异常类型、原因及可用的文本编号或脚本位置。
恢复错位记录时，界面显示保留的改文条数，并将后续原始资源路径切换到恢复副本。
遇到解码问题时，界面显示受影响的记录数，并说明原字节会保留；详细编号样例保存在 manifest 中。

变长回封默认只保存 `rebuild_report.json`，包含校验状态、计数、输出哈希及运行时验证状态。
CLI 的 `rebuild-relocate` 和 `rebuild-pointer-table` 可加 `--audit-log`，额外保存
`reference_sites.jsonl` 和 `relocation_log.jsonl`。`rebuild-auto` 选择重定位策略时也支持此选项。
详细日志只影响记录方式，所有校验始终执行。普通回封成功后会移除同一输出目录中旧的详细日志。

## 验证与记录

回归测试使用 Python 标准库。在工具目录执行：

```powershell
python -X utf8 -B -m unittest discover -s tests -v
```

测试覆盖消息角色、文本变短／变长、重复引用、数值碰撞、加密、异常恢复、场景过滤、旧译文兼容、错位输入恢复和日志输出模式。
可选的整份语料测试通过 `SOFTPAL_TEST_CORPUS`、`SOFTPAL_TEST_VARIANT_CORPUS` 和
`SOFTPAL_TEST_SCENE_CORPUS` 分别指定基础、扩展消息和分场景验证样本，未提供时自动跳过。
`SOFTPAL_TEST_RECOVERY_CORPUS` 可指定包含对应原包的错位输入样本。
`SOFTPAL_TEST_ENCODING_CORPUS` 可指定含无法解码字节的验证样本。
基础样本此前完成 8 组整份资源回封校验；扩展样本核对了 32925 条文本、19491 次已定义布局的
消息调用及明文／加密的变长回封。分场景样本核对了 54841 条文本；按已确认边界导出 118 个场景，
包含此前遗漏的两个连续边界，仍可导入原有 116 个场景文件，包含过滤后的
零编辑往返、旧文件导入及可见文字编辑检查。
验证范围限于已核对的 Sv20 样本和调用布局，游戏内画面尚未验证。

恢复样本核对了 49843 条记录、49807 个文本引用和 95 个场景；保留三条可确认的改文，
还原三处原文拼接。字节兼容样本也核对了 49843 条记录、49807 个引用和 95 个场景，
验证两种提取编码、UTF-8／UTF-16 双行文本及零编辑和变长回封。当前 64 项测试在五项实际语料检查启用时全部通过。

原理说明见 `vm_analysis.md`。历史验证记录和回滚备份在本地保存，工具运行后自动保存本机
GUI 配置。配置、语料、提取结果及调试报告均作为本地生成文件管理。
