# 消息角色与文本引用分析

记录已验证的 Sv20 适配规则及其边界。样本以 A、B、C、D 匿名标识；A、B 属于同一脚本版本的
两种文本布局，均有 2978 条文本。C 有 32925 条文本，D 有 54841 条文本。原始资源保持只读。

## 人名与正文

样本 A 中识别出 1150 次消息调用，其中 `0x20002` 为 1014 次，`0x2000F` 为 136 次。
所有实例均使用四参数格式，参数序号从 0 起：

| 参数序号 | 角色 | 处理方式 |
| ---: | --- | --- |
| 0 | 标志 | 保留数值 |
| 1 | 正文地址 | 绑定正文条目 |
| 2 | 人名地址 | 绑定人名条目；`0x0FFFFFFF` 表示无说话者 |
| 3 | 行号 | 保留数值 |

其中 1051 次调用有人名，99 次无说话者。参数 3 在 21 次调用中恰好等于文本条目地址，
因此数值相等不能作为文本引用的证明。

旧判定允许全角括号进入人名候选，并按候选顺序选择角色，导致两次短独白与人名反转。
修复后，已知格式按参数槽位判定；立即数入栈和参数块写入共用同一解析方法。
实际语料仅修正了四条标签和两次消息配对，其他 2974 条的角色保持一致。

未知格式只有在两个不同文本候选中恰好一个符合人名形态时才形成配对。
全角括号、引号、省略号和语句标点不作为人名形态；无法唯一判定时报告调用位置和候选编号。
实际语料均使用已知定义；参数块变体通过构造用例验证，尚无对应实际语料验证。

样本 C 另外使用 `0x20012`、`0x20013` 和 `0x20014`，每种调用各 16 次。
前两者与上述四参数格式一致；`0x20014` 依次传入正文、人名、行号，不含标志参数。
该样本的五种已定义消息调用共 19491 次，全部核对了正文、人名和行号槽位。
此前一次四参数调用的标志值恰好等于内部配置条目的地址，缺少布局定义使它成为第三个文本候选，
导致分析中断。消息提取与引用重定位现在共用布局定义，三参数消息的参数块也按对应槽位取得行号。

## 选项丢失首字的原因

每个 DAT 条目以四字节编号开头，后接文本和 NUL。脚本引用指向条目起点，显示文本从
引用值加 4 的位置读取。前一条译文减少两个字节时，后一条起点从 `0x28` 移到 `0x26`。
旧 GUI 回封跳过了锚点之前的文本，每条文本也只更新一个数值命中，导致后一条仍引用
`0x28`，于是从第二个全角字符开始显示。

修复按整份脚本中的已确认物理引用位置重定位，锚点仅用于显示参考。
构造用例已复现首字丢失，并验证变短、变长和多处引用都能完整读取。

## 指令与原生调用

宿主 VM 的分发表为 `0x5300B0`，操作数解析函数为 `0x4593D0`。
Sv20 头部占 12 字节，后续按已核对的 33 种指令长度解析。
两份实际语料各包含 85995 条指令，解析恰好到达文件末尾；操作数不会被误当成操作码。
样本 C 的 326039 条指令也按同一宽度表完整解析至文件末尾。

原生调用分发表为 `0x517888`。字符串读取函数 `0x47E2F0` 的 DAT 分支复制完整条目，
包含四字节编号；字符串变量和文件列表使用其他参数类型。
上述原生地址对应 A、B 的宿主。C 的原生分发表为 `0x601450`，消息组表为 `0x601718`，
DAT 读取函数为 `0x43E3A0`。`0x20012`、`0x20013`、`0x20014` 分别进入 `0x434C00`、
`0x4349F0`、`0x433E40`，正文和人名参数沿各自路径进入 DAT 读取函数。
C 的章节标题调用 `0xA0015` 进入 `0x42B000`，弹出一个参数后读取 DAT 条目。
已核对的 DAT 参数深度从栈顶计数，最后一条 PUSH 为 1：

| 调用 | DAT 参数深度 | 用途 |
| --- | --- | --- |
| `0x20002`, `0x2000F`, `0x20012`, `0x20013`, `0x20014` | 3、2 | 正文、人名 |
| `0x60002` | 1 | 选项文本 |
| `0xA0015` | 1 | 章节标题 |
| `0xF0001`, `0xF0002`, `0xF0004` | 1 | 系统文字 |
| `0x120008` | 1 | 字符串复制 |
| `0x120009` | 2，另追踪 `%t` 和 `%T` | 格式化文本 |
| `0x120024` | 3、2、1 | 配置字符串字段 |
| `0x120025` | 2、1 | 配置键和分组 |
| `0x12003B` | 2 | 字符串赋值来源 |
| `0x12005A`, `0x12005C` | 1 | 显示及标签文字 |

格式化调用固定取八个格式参数：`%t` 和 `%T` 读取 DAT，`%f` 和 `%F` 使用文件列表。
立即数经 MOV、寄存器复制再 PUSH 时，重写其原始赋值位置。
遇到改值运算、控制流或调用边界时停止回溯，不推测未知寄存器值。

## 脚本文本包装函数

点位表确认脚本调用 `0xBF4` 对应代码偏移 `0x5B734`，加上头部后为 `0x5B740`。
该函数接收三参数，第一个参数经局部槽 `0x80000001` 传入模板的 `%t` 格式位置，
由此确认 19 条菜单文字赋值的引用语义。

此绑定限定到已验证的头标识 `Sv20 26 16 F4 6A` 和函数位置。
每次回封还会重新核对函数入口及局部参数到 `%t` 的传递关系，避免其他版本因调用编号
相同而误用规则。正常回封不需要读取宿主程序或资源归档。

## 场景导出与历史标签

样本 D 的最后一个场景后有五条资源格式模板和两条日志格式串。原始分析将它们归为 `debug`，
它们只关联格式化或日志调用，不属于任何消息事件。旧场景标签整理却把场景区间内的其他类别
统一提升为 `msg`，最后一个区间又延伸至文件末尾，因此七条内部文字进入了场景译文。

导出现在只根据真实消息事件补充正文／人名标签，其他条目保留原始分类。分场景文件保留场景
边界及已识别的可翻译类别，内部配置、资源、调试文字、未识别条目和未引用条目留在完整 dump。
筛选依据类别，不按字符语言或是否含 `%` 判断；已有可见英文、格式化展示文字和选项照常导出。
该样本仍生成 116 个场景文件，略过七条尾部内部文字及两条内部分支标识。

历史标签整理规则只用于识别旧导出文件的标签别名。导入只接受当前正确标签或该条目按历史规则
实际会得到的标签，继续校验编号和第一行原文，不改变底层分类。完整导入仍要求指定范围的条目齐全；
分场景导入允许省略被过滤的内部条目，并保留它们的原始字节和当前文本。

## 校验与日志

回封前核对源哈希、原文、编号和原始偏移。回封后逐条比较文本原始字节，重新识别引用关系，
并要求脚本的全部差异都位于已确认引用字段。样本 A 的 901 个数值碰撞和样本 B 的
759 个数值碰撞均验证保持原值。

输出经过加密往返、临时文件回读和逐文件替换；普通替换失败会恢复此前文件。
已注入第二个文件替换失败并验证脚本、文本均恢复。此机制不保证断电时整组文件的原子性。

默认保存简洁汇总报告。开启详细日志后，引用依据记录一次，重定位日志仅保存文本编号、
引用位置和新旧地址，避免重复十六进制字段和调用元数据。省略详细日志不省略校验。
旧详细日志仅在新回封成功提交后清理，失败时保留此前结果。

历史整份资源校验涵盖 8 组明文／加密、零编辑、文本变短和变长的回封。
零编辑逐字节一致；变长时未编辑文本原始字节、引用关系和加密往返均通过检查。
样本 C 的零编辑、正文变短及正文／人名变长回封核对了 32909 个引用，保留 5185 个数值碰撞，
并检查了章节标题在文本移动后的引用。样本 D 另验证分场景过滤、历史译文导入、零编辑往返及
场景末尾可见文字编辑后内部条目的保留。
证据摘要和规范读取记录作为本地调试记录保存。
游戏内画面状态仍为 `not_verified`，其他未列出的脚本与调用布局需要另行验证。
